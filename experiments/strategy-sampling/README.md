# 同任务的高层战略采样

2026 年 11 月 17 日。研究者授权使用现有 DeepSeek API key 和 `plan-test` 环境开展本次有界实验。问题是，同一初态下独立采样高层规划时，会不会集中在少数路线，漏掉固定 Executor 能执行的替代路线。

## 结果

[打开交互审核页](./audit.html)，查看逐题覆盖统计、盲审候选计划并对照执行轨迹。

12 个任务生成了 192 份格式有效的计划。32 份代表及参照计划各执行三次，96 条轨迹全部结束，无请求中断。23/24 条参照轨迹和 54/72 条代表轨迹达到环境成功条件。

| 比较 | A 独立采样 | B 提示探索其他路线 |
| --- | ---: | ---: |
| 各取 8 份时，每任务平均路线数 | 2.67 | 3.50 |
| 各取 8 份时，Planner 总 token | 49,213 | 67,781 |
| 每任务取共用 token 上限内的最长前缀，平均路线数 | 2.67 | 3.08 |
| 共用上限内实际纳入的候选数和 token | 96 份，49,213 | 68 份，44,927 |
| 仅看 8 个分层任务，共用上限内平均路线数 | 3.00 | 3.38 |

共用上限内，B 的路线数在 6 题增加、4 题持平、2 题减少。A 和 B 各有 10 题采到了另一条件的对应前缀未见的类别。前缀比较是在生成完成后按用量重算，因此表中的用量是分析纳入量。路线数来自对实际交付计划的文本归类，包含部分无法直接执行的建议。

| 任务与计划 | 动作和结果 |
| --- | --- |
| 2 · T2-13、T2-16 | A 的 8 份里有 7 份先查座位区、1 份先查架子，未采到先查电视柜。B 的代表先到电视柜，取到遥控器 1。A 的代表先到茶几，取到遥控器 4。两份生成计划及对应的两份参照计划各 3/3 成功，每次 4 步。 |
| 18 · T18-08、T18-16 | A 的代表先查台面等开放处，三次各 8 步成功。B 的代表先查抽屉与柜，再转到开放处，三次分别用 25、24、23 步成功。 |
| 14 · T14-08、T14-15 | A 的代表先查边桌，三次各 6 步成功。B 的代表先查垃圾桶和柜，再搜抽屉，三次都耗尽 30 步。 |
| 77 · T77-01、T77-05 | A 的代表三次都先发现并取得 CD，再发现台灯。B 的联合搜索计划三次都先发现台灯，再取得 CD。两份计划都 3/3 成功。手写参照计划则在这个决策上汇合。 |

任务 2 提供了一个可复核的漏采案例。固定 Executor 可以执行两条等步数的路线，A 在本批预算内漏掉了其中一条。任务 14 和 18 表明，额外覆盖的路线也可能失败或增加成本。路线标签由模型助手根据打乱后的计划文本标注，每题一位标注者，少数文本本身可能暗示条件。结果限于一个模型、这个任务样本、标注粒度与三次执行。

API 共收到 192 条 Planner 回复与 1,473 条 Executor 回复，返回用量合计 2,940,065 token。按运行时的 DeepSeek Flash 非高峰公开价估算为 0.109 美元，实际账单以账户为准。[DeepSeek 计价](https://api-docs.deepseek.com/quick_start/pricing/)

生成计划的代表执行用于诊断个案。它适合观察执行是否体现规划中的决策，也保留意外汇合与失败。按条件的终局成功数只描述实际执行的代表，抽取方式随候选路线而变。

## 运行与产物

本地运行目录为 [v04-strategy-sampling-run01](runs/v04-strategy-sampling-run01/)。数据读取自本机现有 ALFWorld `valid_seen` 数据，原始路径记录在 `mapping.yaml` 和运行配置，执行并发为 16。运行环境为 Conda `plan-test`，Python 3.11.16，ALFWorld 0.3.5，TextWorld 1.7.0。首轮复用 `planner-eval` 的 `8019c64e664ba517171a5149674f429d370404ef`，当时的编排脚本为未提交的工作区修改。[实验协议与当前 Recipe](../../src/recipe/strategy-sampling/README.md)

| 位置 | 内容 |
| --- | --- |
| `tasks.jsonl`、`controls.jsonl`、`gamefiles.jsonl` | 实际任务、手写参照计划与游戏文件映射。 |
| `planner_settings.json`、`plans/*.jsonl` | 采样设置、提示、原始 API 回复、提取的计划与路线说明、每请求 token 和响应模型 ID。 |
| `blinded/`、`labels/`、`coverage.json` | 盲标材料、标签理由及候选覆盖率的计算。 |
| `execution_queue.jsonl`、`executions/`、`execution_summary.json` | 实际执行的计划、最终设置、每次动作和环境反馈、终局状态及 API 用量。 |

`runs/` 保存本地原始产物。`executions/run_settings.original.meta` 保留首轮设置的原文，`run_settings.meta` 记录迁移后的提示资源路径。首轮 Executor 使用一条示例。当前 Recipe 不再加载示例，不能续跑首轮轨迹；原始轨迹仍可读取。
